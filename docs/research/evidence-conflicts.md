# 证据冲突处理

本模块在提取和单来源审核之后、覆盖率评估之前比较不同主张；研究冻结和最终交付时再次检查。默认启用，不需要图数据库或新模型服务。`auditor.conflict` 通过现有模型后端、调用预算、持久化输入和 Replay 机制运行。

## 方法来源

| 参考 | 采用的部分 |
|---|---|
| [SciFact, EMNLP 2020](https://aclanthology.org/2020.emnlp-main.609/) | 将证据绑定到目标主张，区分支持、反驳和不足，并保留原文位置 |
| [DRAGged into Conflicts](https://arxiv.org/pdf/2506.08500) | 先区分互补、条件差异、时间变化、事实矛盾及观点分歧，再选择处置 |
| [Astute RAG](https://arxiv.org/html/2410.07176v1) | 双方材料及来源分别保留，不把模型记忆当作可引用证据 |
| [Graphiti](https://github.com/getzep/graphiti) | 将时间和版本作为适用条件；历史材料及旧审核不被覆盖 |
| [Chen 等，EMNLP 2022](https://aclanthology.org/2022.emnlp-main.146/) | 未决冲突允许暂缓唯一答案，不以模型自信作为裁决依据 |
| [GPT Researcher](https://docs.gptr.dev/docs/examples/hybrid_research) | 在报告中解释分歧并引用双方来源 |

这些参考提供方法依据，不能证明本项目模型的实际识别准确率；协议测试中的材料和审核均为明确编写的虚构样例。

## 已实现的流程

1. 每个候选主张保留其证据依赖，即使单来源审核未通过也进入比较池。旧运行的候选关系可以从已有 proposal receipt 恢复。
2. 对本次研究保留的主张做全量两两比较，包含跨章节关系。每对记录独立的输入哈希及完成标记；新增材料只产生新增或变化的任务，预算不足时未完成任务保持可见。
3. 比较角色提取 `ClaimFrame`，记录对象、指标、时间、版本、单位、方法和条件；未知字段允许为空。每个框架及关系判断必须引用所给证据的精确片段。
4. 第二次调用核验原始材料、分类和处置，必须识别双方精确主张版本。视觉材料附带原图及正文/图注上下文，不仅传入模型生成的图片描述。
5. 保存 `ConflictProposal`、`ConflictVerification`、`EvidenceRelationAudit` 和 `ConflictCase`。跨来源反驳是明确审核的 `refutes` 关系，单来源 `not_supported` 不会自动成为反驳。
6. 冲突状态进入规划、覆盖率、章节材料及报告审核。问题要求确认事实时，未决冲突的主张不能用作确定性支持。
7. 冻结报告时绑定比较清单和案件版本；新证据、新快照或新审核使旧覆盖率、规划及冻结失效。交付前再次验证。

## 契约

需求新增可选字段 `answer_mode`：

- `resolve_fact`：默认；要求确认事实。旧契约序列化不写出默认字段，保持兼容。
- `compare_evidence`：要求梳理不同证据。允许完整、有引用地呈现争议，不等于接受双方主张都为真。

需要交付争议时，应显式添加研究阶段检查，例如：

```json
{
  "check_id": "R1.conflicts",
  "code": "conflict_disposition",
  "stage": "research",
  "params": {
    "allowed": ["resolved_by_scope", "unresolved_disclosed"]
  },
  "reason": "保留双方证据，明确适用条件和未决分歧"
}
```

`compare_evidence` 与上述检查共同允许争议交付。`resolve_fact` 遇到未决冲突时，只有 `allow_unknown`、`unknown_check_ids`、实际调查记录和报告披露都满足契约，才能成为 `bounded_unknown`。

没有写 `conflict_disposition` 并不能绕过已知冲突。案件为空也不等于检查完成：全部比较任务必须有当前有效结果。

## 处置边界

| 情况 | 当前行为 |
|---|---|
| 两次审核确认无冲突或互补 | `dismissed`，完成比较，不影响正常支持 |
| 条件或时间不同，且原主张已经明确限定适用范围 | `resolved_by_scope`；保留双方，不删除旧材料 |
| 模型提出条件不同，但原主张仍过于宽泛 | 保持未决；下一轮应提取并审核限定后的主张 |
| 同条件下事实相反、审核不确定 | `unresolved_disclosed`；事实确认不能通过 |
| 声称有更正、复现或应加权选择，但缺少独立核验机制 | 保持未决，不自动让一方失效 |
| 需要用户价值判断 | `requires_user_judgment`，依赖该判断的需求不自动放行 |

`resolved_by_correction`、`resolved_by_reproduction`、`weighted_conclusion` 仍是契约中可表达的目标处置，但此版本不会仅凭模型提出这些标签就判定解决。自动验证更正、复现产物和加权结论是后续扩展，不属于已实现能力。系统可以继续检索这些依据并提取更精确的主张。

不会按照网页数量、发布时间、模型自信分数或单一权威等级自动选边。当前不新增观测独立性证书算法；已有来源根信息随材料传递，不能据未知来源关系宣称独立印证。

## 报告、视觉与复用

未决争议通过已有 `DisputeFact` 表达：必须引用当前 `conflict_version_id`、全部双方证据 ID，并在正文中实际使用该 fact。不能只在 facts 数组里放一条没有被引用的争议。渲染和 `report.json` 导出同时包含双方引用。

图文冲突会保存可定位的正文/图注跨度作为第二份候选证据。找不到第二侧原文时，保持视觉缺口，不能复制一个证据 ID 伪造双边引用。视觉缺口本身仍需要视觉审核通过，普通文本裁决不会自动解除视觉阅读义务。

跨运行导入保留双方证据及历史审核。旧裁决没有本次任务的通行权；只有完整、当前的本地双方比较才可解除复用阻断。普通 `no_objection` 不足以解除冲突。旧报告作为历史交付保留。

## 恢复与成本

所有比较和复核计入现有 `research` 预算。缓存键包含双方材料、契约、提示词、策略版本及可用的模型配置标识。只有完成关系记录与案件持久化后，才保存比较完成标记。崩溃重试使用同一输入与响应，不重新计费已完成的调用。

第一版优先保证召回范围可解释，采用 O(n²) 候选比较，每个未缓存的材料对需要两次角色调用。大研究可能耗尽预算；系统会报告未完成比较，不静默截断并宣称无冲突。后续可引入对象/指标索引及候选召回评测，在保留未处理清单的条件下减少调用。

## 验证与后续扩展

`tests/research/test_conflicts.py` 覆盖支持/反驳、条件拆分、伪造引用、漏报、预算中断、崩溃恢复、新版本失效、争议报告与有边界未知。其他研究测试覆盖旧 Replay、复用及视觉协议。

后续模型评测应使用适用的 SciFact、CONFLICTS 样本及项目人工标注案例，分别测量候选召回率、误报率、错误关闭率、反证遗漏率与调用成本。不能把虚构 Replay 测试通过率当成模型准确率。
